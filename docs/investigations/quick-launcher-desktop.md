# 快捷启动 Windows 真机验收

日期：2026-11-18。使用工作区的 `src-tauri/target/release/focusd-island.exe`，以独立应用标识和临时 WebView2 配置启动。已安装版本在验收期间继续运行。

## 观察记录

- Windows 枚举到两个显示器。主屏工作区物理坐标为 `(0, 0)–(2560, 1380)`，缩放 125%。副屏为 `(2560, 41)–(4800, 1369)`，缩放 150%。按当前设计，面板外框预期分别为 `(855, 402)–(1705, 977)` 和 `(3170, 360)–(4190, 1050)`。
- Windows 枚举确认当前构建创建了标题为「fly-island 快捷启动」的原生窗口，初始隐藏。当时窗口 DPI 为 120，未显示时的初始坐标不用于判断居中。
- 尝试以记事本为前台目标发送 `Alt+Space` 时，桌面控制返回 `USER_INPUT_ACTIVE`，确认按键没有送出。这次尝试无法判断热键是否注册成功。
- 从本机时间 15:01:31 起只读观察了 3 分钟，期间没有记录到面板由隐藏变为可见，也没有收到实体按键结果。随后关闭了隔离实例，并确认已安装版本仍在运行。

## 双击 Ctrl 对照实验（2026-11-18）

- 新构建的隔离实例启动后，桌面控制未找到该进程可定位的顶层窗口，因此 `press_key` 返回 `window_target_not_found`；观察者在窗口出现前退出，没有产生可见性记录。此结果为输入通道限制，不是应用功能失败。
- 随后对已安装版本（PID 35076）发送 Ctrl 时，桌面控制返回 `USER_INPUT_ACTIVE`，确认按键未送出。
- 在未发送任何输入的前提下，Windows 枚举确认该进程已创建标题为「fly-island 快捷启动」的隐藏窗口。

因此，双击 Ctrl 的 Windows 实机开合、Ctrl+C 是否仍复制到剪贴板、以及双击是否保持静默，均未通过桌面输入通道验证；识别逻辑已由 Rust 单测覆盖。
