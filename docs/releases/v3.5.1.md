## 更新内容

- **快捷启动新增「双击 Ctrl」触发方式**。在设置中选择后，快速单独按下并松开左右 Ctrl 各一次即可打开面板；普通组合键和默认的 `Alt+Space` 仍然可用。识别逻辑会忽略与其他键或修饰键同时按下的 Ctrl、长按和自动重复，让 `Ctrl+C` 等组合键照常交给原程序。原有已录入的组合键会保留。
- 保留 v3.5.0 的**快捷搜索启动面板**与**双屏截图黑屏修复**：可搜索应用、指定文件夹中的文件和网址，支持方向键选择、回车打开；双屏截屏在高级色彩与 DXGI 色彩空间不一致时改用正确的抓屏路径。

### 验证范围

- 双击 Ctrl 的识别有 Rust 单测覆盖：两次干净松开才触发，`Ctrl+C`、左右 Ctrl 重叠、长按、自动重复、已有修饰键、超时和中间插入按键均不会误触。前端检查、回归页、Rust 测试与正式签名构建已通过。
- **尚未在真实 Windows 桌面验证**双击 Ctrl 打开面板、`Ctrl+C` 仍可复制且不弹面板、双击保持静默。桌面输入通道对测试按键返回 `USER_INPUT_ACTIVE`，因此不能把这些项目写成验证通过。
- 快捷启动的浏览器回归覆盖过滤、排序、键盘选择和打开回调；真实桌面上的全局快捷键、失焦关闭、跨屏弹出、打开应用/文件/网址仍未亲验。
- 截图仍待实机验证的场景包括 scRGB、纯 SDR 单屏、纯 HDR 单屏、跨屏区域抓取、长截图与贴图编辑的完整流程，以及退出截图时显示器重排。跨屏 HDR 区域抓取目前只取一个相交的 HDR 输出。

## What's new

- **Quick launcher can now open with a double-tap of Ctrl**. Choose this trigger in Settings: quickly press and release Ctrl by itself twice to open the panel. Regular key combinations and the default `Alt+Space` remain available, and your existing combination is kept. Detection ignores Ctrl presses involving other keys or modifiers, long holds, and key repeat, so combinations such as `Ctrl+C` continue to reach the original app.
- The v3.5.0 **quick launcher** and **dual-monitor screenshot black-screen fix** remain included: search apps, files in selected folders, and URLs; use the arrow keys and Enter to open results. Screenshots now choose the capture path using the DXGI color space when Advanced Color and DXGI disagree.

### Validation scope

- Rust unit tests cover double-tap recognition: it fires only after two clean releases, while `Ctrl+C`, overlapping left/right Ctrl, long holds, auto-repeat, existing modifiers, timeouts, and intervening keys do not trigger it. Frontend checks, browser regression pages, Rust tests, and the signed Windows release build passed.
- **Real Windows desktop verification is still outstanding** for opening the panel with double-tap Ctrl, confirming `Ctrl+C` still copies without opening the panel, and confirming a clean double-tap stays silent. The desktop input channel returned `USER_INPUT_ACTIVE` for test keystrokes, so these must not be reported as verified.
- Launcher browser regression tests cover filtering, ranking, keyboard selection, and open callbacks. The global hotkey, dismissal on focus loss, opening the panel on either monitor, and opening apps, files, and URLs on the real desktop have yet to be verified.
- Screenshot scenarios still awaiting hardware verification include scRGB, SDR-only and HDR-only single-monitor setups, cross-monitor region capture, the full scrolling capture and pinned-image editing workflows, and display rearrangement while exiting capture. HDR region capture currently uses one intersecting HDR output.
