## 更新内容

- **新增完整可配置的自动更新**。在「设置 → 关于」里可以设置自动更新总开关（默认开）、「下载后自动安装并重启」（默认开）和检查间隔（1 / 6 / 12 / 24 小时，默认 6 小时）。开启后除启动检查外会按间隔定时检查；自动安装开启时下载完成立即安装并重启，关闭时保留原来的「待办提示 + 手动点重启更新」。关闭总开关后不再定时检查或自动安装，仍可手动检查。
- 启动、定时、手动检查与安装共用流程锁，不会并发下载或重复弹提示。设置持久化并在重启后恢复；独立设置窗口通过现有更新事件镜像主窗口状态，不重复下载。
- 保留 v3.5.1 的**双击 Ctrl 快捷启动**、v3.5.0 的**快捷搜索启动面板**与**双屏截图黑屏修复**。

### 验证范围

- 前端检查、浏览器回归、Rust 测试与 Windows 构建均通过。新增单测覆盖设置默认值与持久化、定时间隔、禁用后停止调度、流程去重、自动安装分支和跨窗口状态；设置回归页覆盖开关、间隔及重启后读回。

## What's new

- **Fully configurable automatic updates**. Settings → About now has a master switch (on by default), "Install and restart after download" (on by default), and a check interval of 1, 6, 12, or 24 hours (6 by default). Besides the startup check, the island checks on the chosen interval. With auto-install on, a downloaded package installs and restarts immediately; with it off, the existing update todo and manual "Restart & update" remain. Turning the master switch off stops scheduled checks and automatic installs, while manual checks still work.
- Startup, scheduled, manual checks and installs share one flow lock, so no second download or duplicate prompt starts while one is running. Settings persist across restarts, and the separate settings window mirrors the main window's state through the existing update events without downloading again.
- The v3.5.1 **double-tap Ctrl launcher trigger**, v3.5.0 **quick launcher**, and **dual-monitor screenshot black-screen fix** remain included.

### Validation scope

- Frontend checks, browser regressions, Rust tests, and the Windows build passed. New unit tests cover defaults, persistence, scheduling intervals, disabling the schedule, flow de-duplication, the auto-install branch, and cross-window state; the settings regression covers the switches, interval, and reading saved choices back.
- **The real download, automatic install, and restart flow was not verified on a real desktop**: it replaces the installed version and force-restarts the app, which cannot be reproduced safely in the current validation environment. Update-package signature verification, passive install mode, and endpoint configuration were not changed.

## Downloads

Windows x64 EXE and MSI installers are available with their `.sig` files. `latest.json` is the in-app update manifest, and `SHA256SUMS.txt` lists the installer checksums.
